# GATES.md — every gate named in atlas-0…7 and atlas-9, its seeded fault, and its CI wiring

atlas-8 step 1 deliverable. Built by grepping every subplan's "Gates" progress-log lines and every
`tests/**`/`scripts/**`/`e2e/**` file for "fault"/"seeded"/"CANNOT FAIL"/"red fixture", then
verifying a sample of each pattern by reading the actual file. Two structural patterns cover almost
everything in this repo (see `CLAUDE.md`'s own rule: "every gate ships with a seeded fault... a
check that cannot fail is not a check"):

- **build-time invariant**: `scripts/<name>.mjs` (CLI) + `scripts/<name>-core.mjs` (pure) +
  `tests/<name>.test.ts` (drives the core fn through synthetic fixtures, including a red one).
  `size-budget` additionally gets a real, CI-level red-fixture build (`pages.yml` builds
  `tests/fixtures/size-budget-{static-duckdb,worker}/` and inverts the checker's exit code against
  it) — the strongest-wired pattern in the repo.
- **pure-logic / source-scan gate**: a `tests/**/*.test.ts` that asserts the real rule against real
  fixtures AND plants a fault (inline in the same file — a wrong implementation kept beside the
  right one, e.g. `rmod.test.ts`'s `noGuard`/`naive` — or a committed fixture directory a scanner is
  pointed at, e.g. `tests/fixtures/map/fitbounds-fault/`) and asserts the checker rejects it.

Both patterns prove themselves on every ordinary `npm test` — no extra machinery needed. The
**third** pattern, `npm run test:faults` (`scripts/test-faults.mjs`), exists for the minority of
gates where the fault must be applied to the REAL file `src/` ships (not a parallel copy), because
the property under test is about that exact function: it worktrees HEAD, applies a committed unified
diff under `tests/faults/*.patch`, runs the named gate, asserts RED, and discards the worktree.

**Counts** (this table): **~98 gates** inventoried · **~93 already carry a committed, verified
seeded fault** (pattern 1 or 2, self-proving on `npm test`) · **12 wired into `npm run test:faults`**
(pattern 3; 3 added in step 1, 1 with Deliverable 4's feedback link, 3 added in step 3 — two
accessibility ones and the `verify` job's — 1 added in step 3's fix round — `modal-esc-delegated.patch`,
fix list #1 — 1 added 0.10.19 for G-25's `Sel.out` map wiring, 1 added 0.10.20 for the basemap
that silently never painted, 1 added 0.10.21 for fix 1's scores-lens map inputs moving back
onto panel-only UI, and 1 added 0.10.22 for the style queue settling on `"idle"` instead of the
issued style's own `"style.load"`) · **4 were "CANNOT FAIL" or scope-gapped before step 1 and are now
rewritten** (marked ✅ FIXED below) · **0 remain CANNOT FAIL** as of 0.10.20.

Step 3's three faults are the first **browser-driven** entries in `test:faults`. They need a real
browser against a real build of the patched tree, so each runs on its own port —
`PW_PORT` for the two Playwright ones (`playwright.config.ts` honours it and, when it is set, never
reuses a server it did not start) and `VERIFY_BASE_URL` for `verify-missing-export` (`verify.mjs`
reuses a server it finds, by design). Without that, a `vite preview` already answering 4331 from the
unpatched checkout would serve the wrong bytes and the fault would "pass". The CI `test:faults` job
therefore installs chromium.
